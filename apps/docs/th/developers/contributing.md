# การมีส่วนร่วม

ขอบคุณที่ช่วยพัฒนา Samnak Chat หน้านี้สรุปว่าการเปลี่ยนแปลงหนึ่งต้องมีอะไรก่อนจะถูก merge ไฟล์ฉบับเต็มอยู่ที่ [`CONTRIBUTING.md`](https://github.com/KPV2004/samnak-chat/blob/main/CONTRIBUTING.md) ในที่เก็บโค้ด

## ก่อนเริ่ม

1. อ่าน[สถาปัตยกรรม](/th/developers/architecture) โดยเฉพาะกฎการพึ่งพา และกฎของโมดูลใน[โมดูลและกฎ](/th/developers/modules)
2. อ่าน [`AGENTS.md`](https://github.com/KPV2004/samnak-chat/blob/main/AGENTS.md) ซึ่งอธิบายการแบ่งงานระหว่างผู้วางแผนกับผู้ลงมือ และกฎตายตัวที่มาจากสถาปัตยกรรม
3. เลือกงานที่ยังเปิดอยู่ใน [`tasks/todo.md`](https://github.com/KPV2004/samnak-chat/blob/main/tasks/todo.md) ใช้หนึ่งแบรนช์ต่องานหนึ่งงาน ตั้งชื่อ `task/<id>-<slug>`
4. เขียน [Conventional Commits](https://www.conventionalcommits.org/) ที่อ้างถึงงาน เช่น `feat(platform): in-memory event bus (M0-02)`

ตั้งเครื่องของคุณด้วย[ตั้งค่าสำหรับพัฒนา](/th/developers/setup)

## การเปลี่ยนแปลงหนึ่งต้องมีอะไร

- **เขียนเทสต์ก่อน** สำหรับตรรกะใน domain และ use case ให้เขียนเทสต์ที่ล้มเหลวก่อน แล้วจึงเขียนโค้ด ครอบคลุมกรณีสำเร็จ กรณีไม่มีสิทธิ์ และข้อมูลที่ไม่ถูกต้อง
- **เซิร์ฟเวอร์** `go test ./...` ต้องผ่าน และใน CI รันด้วย `-race` ความครอบคลุมของแพ็กเกจ domain และ use case ต้องอยู่ที่ 80% ขึ้นไป
- **เว็บ** พฤติกรรมใหม่ทุกอย่างมี component test และ `npm test`, `npm run lint` และ `npm run build` ต้องผ่าน
- **การเปลี่ยน API** รัน `make openapi` แล้ว commit ผลลัพธ์ CI จะล้มเหลวเมื่อ `apps/server/api` หรือ `packages/core/src/api` ไม่ตรงกับโค้ด
- **การเปลี่ยนโมดูล** รัน `check-modules.sh` กับชุดโมดูลที่ใช้การเปลี่ยนแปลงนั้น
- **Migration** ต้องรันได้บนฐานข้อมูลว่าง
- **เอกสาร** อัปเดตเอกสารเมื่อพฤติกรรมที่ผู้ใช้เห็นเปลี่ยน และเพิ่มรายการใต้ `[Unreleased]` ใน[บันทึกการเปลี่ยนแปลง](https://github.com/KPV2004/samnak-chat/blob/main/CHANGELOG.md)

อย่าปิดการตรวจเพื่อให้ผ่าน นั่นหมายถึงไม่ใช้ `//nolint` ไม่ข้ามเทสต์ และไม่อ่อนข้อตรวจลง เว้นแต่ผู้ดูแลจะอนุมัติ

## CI รันอะไร

ทุกการ push รันงานเหล่านี้

| งาน | สิ่งที่ตรวจ |
| --- | --- |
| `go` | `go vet`, `golangci-lint`, `go test -race ./...` และเกณฑ์ความครอบคลุม |
| `node` | `npm run build`, `npm run lint` และ `npm test` |
| `openapi` | ไฟล์ OpenAPI ที่ commit ไว้และไทป์ที่สร้างขึ้นตรงกับโค้ด |
| `modules` | เซิร์ฟเวอร์เริ่มได้กับทุกชุดโมดูล และเส้นทางตอบตามที่คาด |
| `images` | อิมเมจของเซิร์ฟเวอร์และเว็บ build ได้ทั้ง `linux/amd64` และ `linux/arm64` |

ผู้ดูแลจะรีวิวและ merge pull request แต่ละรายการ

## นิยามของงานที่เสร็จ

- เทสต์ครอบคลุมกรณีสำเร็จ กรณีไม่มีสิทธิ์ และข้อมูลที่ไม่ถูกต้อง
- CI ผ่าน ทั้ง lint เทสต์ และการตรวจขอบเขตโมดูล
- ไฟล์ OpenAPI และไทป์ของเว็บถูกสร้างใหม่
- Migration รันได้บนฐานข้อมูลว่าง
- เอกสารอัปเดตแล้ว ถ้าพฤติกรรมที่ผู้ใช้เห็นเปลี่ยน
